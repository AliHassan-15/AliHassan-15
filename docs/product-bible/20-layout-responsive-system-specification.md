## 0. Purpose

**Why.** Documents 05, 14, and 15 define how space and structure serve understanding. Without a layout system specification, surfaces invent private spatial arrangements and orientation collapses into collage.

**Specification.** This document specifies how information occupies space throughout EOS while remaining completely implementation-independent. It specifies layout systems. It applies Documents 05, 07, 14, and 15; it does not redefine them. It never defines color, typography, components, motion, navigation ownership, interaction ownership, construction methods, measurements, breakpoints, spacing scales, grids as construction recipes, or layout inventories. Exact layout recipes, measurements, and responsive inventories remain **Deferred** until later governed implementation specifications. Deferred gaps are never filled by fashion catalogs presented as decided truth.

**Failure Conditions.** Layout systems that contradict Documents 00–19. Redefinition of Design Language, Interaction Language, Design Constitution, or UI Constitution. Construction-bound recipes treated as the layout system itself. Invented layout inventories presented as locked.

## 1. Layout Philosophy

**Why.** Philosophy already locked in Documents 05, 14, and 15 must not be rewritten as specification costume.

**Specification.** This section applies Documents 05, 14, and 15 layout and composition law only; it does not redefine or replace them. Layout organizes for comprehension: information-rich, highly structured, intentionally spacious. Hierarchy before density. Systems before screens. Understanding before decoration. Purpose before beauty. Progressive unfold outranks simultaneous overload. Layout clarifies relationships among systems, decisions, and proof. Luxury through restraint. The visitor must never think about arrangement — only the engineering. Layout never invents page trees owned by Information Architecture. Layout never invents a third public product surface. Same message; different depth. Five-year defensibility outranks temporary layout fashion.

**Failure Conditions.** Collage without structure. Layout that forces attention to arrangement instead of engineering. Philosophy redefined under the name of systems. Entrance layout recreating destination. Third public surface via layout.

## 2. Information Density

**Why.** Density without hierarchy becomes noise. Emptiness that hides useful engineering becomes failure.

**Specification.** This section applies Documents 05, 14, and 15 hierarchy-before-density law to layout density; it does not redefine them. Organized complexity is permitted; accidental complexity is refused. Density may increase when content is more technical and understanding benefits. Density must never obscure primary meaning. Extremely minimal compositions that conceal useful engineering information are refused. Overly dense layouts that destroy scan and calm are refused. Exact density inventories remain **Deferred**.

## 24. Layout Review Standards

**Why.** Layout without review becomes collage culture. Review enforces Documents 05, 12, 14, and 15.

**Specification.** Layout system review must answer:

1. Does this obey Documents 00–20?  
2. Does it apply Documents 05, 07, 14, and 15 without redefining them?  
3. Does hierarchy come before density?  
4. Does the visitor focus on engineering rather than arrangement?  
5. Is progressive depth optional; is L1 clear first?  
6. Do entrance and destination keep same message with different depth?  
7. Does orientation remain recoverable (where / why / next / return)?  
8. Do accessibility and performance hold as baseline across contexts?  
9. Would we still choose this in five years?  
10. Does any Document 12 accessibility or performance quality dimension fail?

One failed required answer voids approval. Fashion is never a valid yes. Schedule pressure does not redefine Done.

**Failure Conditions.** Review that asks only whether layout occupies space. Novelty accepted as craft. Silent conflict with locked documents. Approval without five-year defensibility. Done redefined by schedule.

Hierarchy before density.
