## 0. Purpose and constitutional rules

### 0.1 Purpose

Content Architecture defines content ownership for every Information Architecture node.

It states only what prior locked constitutions already establish about required, optional, and Deferred content and where evidence belongs.

### 0.2 Conflict rule

If any instruction conflicts with Vision, Identity, Discovery, Creative Direction, Design Language, Motion Language, Interaction Language, or Information Architecture, stop immediately and ask. Do not silently reconcile.

### 0.3 Provenance rule

Every content claim must be traceable to a prior constitutional document. If unsupported, mark **Deferred**. Never invent content. Never strengthen Discovery. Never interpret evidence.

### 0.4 Separation rule

This document must not define visual design, typography, spacing, components, layouts, motion, interaction, frontend, technology, implementation, copywriting, marketing, or storytelling.

Exact prose wording (except Identity-approved exact lines cited as required content types) belongs to later Content / Writing work — **Deferred** where not already locked as Identity exact text.

Exact page trees / section sequences remain Deferred per Information Architecture (IA-01–IA-04).

## 12. Relationships between content blocks

**Source:** IA §6; Identity §19–§20, §25.5; Vision §10–§11.

| Relationship | Content rule |
|--------------|--------------|
| Entrance → Destination | README invites Companion; does not replace Companion content depth |
| Destination → Evidence | Companion proof points to repos, diagrams, case studies, write-ups |
| Same message / different depth | Shared identity content; Companion deeper |
| Projects ↔ Research | Research content inside case studies until dedicated Research earned |
| Projects ↔ Writing | Case studies carry architecture/decisions/trade-offs/lessons; standalone writing only when ideas transcend one project |
| Five systems ↔ two surfaces | System content lives inside GitHub + Companion only |
| L1 → L2 → L3 | Optional depth classes; concrete wiring Deferred |
| Identity / About ↔ Contact | Professional channels only; LinkedIn/Email Deferred |
| Projects ↔ AI class | Preserve AI essential vs conventional-by-design; do not regroup |
| Career ↔ Future projects | “What is being built next” uses placeholder + Deferred next-work content |
| Evidence ↔ Claims | No measured-outcome claims without Discovery evidence; DeepMed wait-time/market = vision/objectives language only |
