# 0. Purpose

This project exists to build a **personal engineering product**, not a portfolio.

The GitHub profile, companion website, design system, animations, engineering quality, motion language, and storytelling must work together as one cohesive product.

The objective is not to demonstrate that animations can be built.

The objective is to demonstrate the qualities expected of a strong software engineer:

* Systems thinking
* Engineering maturity
* Product craftsmanship
* Design judgment
* Technical excellence
* Attention to detail
* Long-term maintainability

The final experience should communicate those qualities before the visitor reads a single paragraph.

---

# 1. Mission

Create an engineering experience that reflects the quality of the software its creator would build.

Every interaction, transition, illustration, visualization, and line of copy must reinforce the perception of thoughtful engineering.

This is not a résumé.

This is evidence.

---

# 2. North Star

If every animation, every color, every component, every paragraph, and every interaction were questioned by a room of experienced engineers and designers, every decision should have a clear, defensible reason.

Nothing should exist merely because it looks impressive.

---

# 3. Product Definition

The product consists of two connected experiences.

## Product A — GitHub Profile

Purpose:

* Create a memorable first impression
* Communicate identity quickly
* Showcase engineering quality within GitHub's constraints
* Invite visitors into the deeper experience

GitHub is the entrance.

It is not the destination.

---

## Product B — Companion Experience

Purpose:

Tell the complete engineering story through:

* projects
* architecture
* systems thinking
* research
* writing
* engineering philosophy
* interactive visualizations

This is where richer motion and interaction belong.

---

# 4. Success Definition

The project is successful if visitors conclude:

* This engineer cares deeply about quality.
* This engineer understands systems.
* This engineer builds thoughtfully.
* This engineer finishes work to a high standard.
* This engineer communicates clearly.

The project is **not** considered successful simply because it contains many animations or visual effects.

---

# 5. Core Principles

## Principle 1 — Engineering First

Visual design supports engineering.

Engineering never supports decoration.

### Rationale

Strong products are remembered because they solve problems elegantly, not because they use more effects.

### Review Question

Does this feature communicate engineering quality?

If not,

remove it.

---

## Principle 2 — Purpose Before Beauty

Every visual decision must solve one of these problems:

* explain
* guide
* reveal
* organize
* reinforce
* delight appropriately

Never decorate without purpose.

---

## Principle 3 — Luxury Through Restraint

Luxury products rarely contain more.

They contain only what deserves to remain.

Whitespace is valuable.

Silence is valuable.

Pacing is valuable.

---

## Principle 4 — Consistency Creates Trust

Spacing

Typography

Motion

Color

Layout

Language

must feel like they were created by one team with one vision.

---

## Principle 5 — Truth Builds Credibility

The product represents real work.

Never exaggerate achievements.

Never invent experience.

If information is missing,

ask.

---

# 6. Design Constitution

The visual language should communicate:

* confidence
* precision
* clarity
* refinement
* intelligence
* calmness

It should never communicate:

* chaos
* excess
* trend chasing
* gimmicks

---

# 7. Motion Constitution

Motion exists to communicate.

Not entertain.

Preferred behaviors:

* reveal
* focus
* connect
* breathe
* transition
* emphasize

Avoid:

* endless loops
* unnecessary spinning
* distracting motion
* animation for its own sake

---

# 8. 3D Constitution

3D is optional.

It must justify its existence.

Examples of appropriate use:

* camera depth
* architecture visualization
* environmental storytelling
* spatial navigation

Examples of inappropriate use:

* random floating objects
* decorative planets
* unrelated geometry
* effects that reduce performance without improving understanding

---

# 9. Audio Constitution

Audio is optional.

Muted by default.

Visitors must choose to enable sound.

If enabled, audio should create atmosphere without distracting from the experience.

---

# 10. README Constitution

The GitHub README should:

* communicate identity immediately
* establish credibility
* demonstrate craftsmanship
* guide visitors naturally toward the companion experience

It should not attempt to recreate the entire website.

---

# 11. Companion Constitution

The companion site is not a résumé.

It is an interactive product experience.

Visitors should leave understanding:

* how problems are approached
* how systems are designed
* why architectural decisions were made
* what has been built
* what is being built next

---

# 12. Performance Constitution

Performance is a feature.

The experience must remain responsive on typical modern laptops and phones.

Every animation and visual effect must justify its performance cost.

---

# 13. Accessibility Constitution

Accessibility is part of quality.

Support includes:

* keyboard navigation
* reduced-motion mode
* sufficient contrast
* semantic structure
* descriptive labels
* responsive layouts

These are baseline expectations, not optional enhancements.

---

# 14. Decision Framework

Whenever uncertainty exists, apply these questions in order:

1. Does this improve clarity?
2. Does this strengthen storytelling?
3. Does this reinforce engineering quality?
4. Does this improve the user's understanding?
5. Does it remain performant?
6. Does it remain accessible?
7. Does it fit the design language?
8. Can it be maintained?
9. Would we still choose this decision in five years?

If any answer is "no," reconsider the feature before proceeding.

---

# 15. Forbidden List

Do not introduce features simply because they are fashionable.

Avoid patterns that make the experience feel generic or overloaded.

Examples include:

* excessive visual clutter
* unrelated decorative animations
* repetitive technology badges
* multiple competing accent colors
* inconsistent typography
* overly dense layouts
* effects that distract from content

---

# 16. Quality Standard

Before any feature is considered complete, it must satisfy:

* Functional quality
* Visual quality
* Motion quality
* Engineering quality
* Performance quality
* Accessibility quality
* Content quality

If one area falls short, the feature is not complete.
